# pycode 设计

pycode 是本地终端编程 Agent，支持非交互 CLI 和 Textual TUI。本轮实施范围及验收规则见
`五阶段改造计划.md`；原始实施记录归档在 `archive/第二个计划-实施记录.md`。
本设计随五阶段改造交付更新，测试证据以最终验收记录为准。

## 执行与依赖

Python 3.11+。`deepagents==0.7.23` 的 `create_deep_agent` 是唯一模型与工具循环；
LangChain 提供工具、模型适配与 middleware，LangGraph 管理活跃运行和 interrupt。
应用负责领域策略、持久化、审批及资源生命周期，不再实现另一套 Agent 循环。

源码按功能组织：kernel、agent、session、context、models、tools、sandbox、snapshot、
memory、skills、mcp、hooks、plans、team、ui，以及 app 组合根。
纯 domain 不做 I/O，domain/ports/service 不依赖框架。跨功能只使用公开 API，
统一入口是 `app/bootstrap.py:compose_application`；各功能的 `module.py` 自行装配内部适配器，
应用只连接其产物。Skills/MCP 可独立替换或禁用；子作用域保留所选实现。
`kernel` 统一四层，业务算法归还各功能；静态检查同时验证模块边界及依赖无环。
评测 `evals/`、开发脚本 `scripts/` 和历史 `archive/` 独立于产品运行时。

## 会话、工具与恢复

完成消息和产品事实以 JSONL 保存，支持会话树、分支、命名和文件回退。
模型上下文是对原始历史的投影，摘要或大输出驱逐不改写用户看到的原始事实。
大输出保存一个完整对象，模型与 UI 可按需要分段读取。

工具执行依次经过声明/schema、权限、hooks、快照和结算边界。
正式结果持久化后才发送工具完成事件；取消、审批中断和关键持久化失败不会伪装成普通工具错误。
主聊天 checkpoint 只在当前进程的内存中。进程重启后依据 JSONL 修复缺失结果并标记中断，
不重用旧审批、不自动重跑旧工具。恢复后的用户需要根据实际文件状态发起新指令。

## 模型与上下文

Provider 配置显式声明模型、协议、窗口、输出额度及能力，密钥通过环境变量引用。
主模型可配置有序 fallback；取消、认证/配置错误和程序缺陷不触发自动切换。
请求、重试和实际用量绑定真实 Provider/模型/用途，不把失败流片段计为成功消息。

关闭框架默认摘要，使用 pycode 的后台摘要与安全采用边界：约 80% 窗口触发，
来源、配置、分支和保留边界一致后才能采用。预算包含系统提示和本轮实际工具 schema。
只读工具可并发，写入有锁和屏障，同工具同参数连续失败三次后拒绝重复执行。

## 记忆与项目指令

LangMem 管理主动记忆工具和一次后台 Store Manager 整理；pycode 管理每作用域的
`memory.json`、触发时机、变更日志及用户撤销。长度、总数和疑似密钥过滤在纯策略层执行。
整理结果直接生效，失败记日志且不重试，不阻断聊天；`/memory undo` 校验整理后状态再恢复。

用户 `~/.pycode/AGENTS.md` 和受信任项目 `AGENTS.md` 经 MemoryMiddleware 加载。
项目指令只有 `--trust-project` 时启用。少量笔记全部召回，超过阈值后由受控查询选择。
后台记忆模型关闭 thinking 与 reasoning_effort，以免与结构化强制 tool_choice 冲突；
主聊天的 thinking 配置保持用户设置。

## 进程内团队

lead 通过普通工具派出子 Agent，配置同时运行 1–4 个。每个子 Agent 拥有独立会话，
只有 readonly 和独立 Git worktree worker 两种固定权限；临时角色说明不能扩大权限。
调度、通信和等待使用 asyncio，不使用 HTTP、端口或 Agent Protocol。

收件箱在模型调用前注入，lead 空闲时由新消息或完成通知唤醒。任务板、消息和状态保存到
独立 JSONL 账本，子会话与 lead 关联。审批统一转发主界面并标明来源。
取消 lead 会收拢所属子任务；重启标记中断，不自动续跑。

worker 合并前先 review，内容绑定不可变 Git tree，合并还绑定目标 branch/HEAD。
每次 merge 单独审批，执行前后重新校验；冲突保留工作树并在 worker 中解决，
确认集成后才清理。Git 集成事实与“测试已通过”分别记录。

## 子进程与沙箱

Bash、command Hook 和 Python Skill 使用白名单子进程环境，默认不传 API Key、token、
密码或 AWS 凭据。`--pass-env NAME` 可重复显式加入 SSH_AUTH_SOCK、HTTPS_PROXY 等普通变量；
凭据形态名称仍拒绝，Hook 的显式 `$ENV.NAME` 引用遵循原有审批和配置规则。

macOS Seatbelt 限制工作区写入，并保护内部状态、私有目录及 `.env*`。
工作区 `.env.example` 是精确的例外，不将通配符或路径正则误当成扩大授权。
`on-auto` 只自动批准纯策略白名单中的只读命令；worker 命令无法在隔离不可用时回落执行。
其他平台的可用能力以 doctor 和实际后端结果为准。
