# Java源码解析：工具注册与执行框架
本文深入 MiniCode 项目的工具系统，看看「注册 → 发现 → 审批 → 执行」这条主线在 Java 21 里是怎么实现的。

## 完整流程概览

工具系统的完整生命周期从系统启动到工具执行，分为五个阶段：

### 阶段 1：启动时注册（System Startup）

```java
// Agent 构造函数
ToolRegistry registry = ToolRegistry.createDefault();
  ↓
registry.register(new ReadFileTool());
registry.register(new WriteFileTool());
registry.register(new EditFileTool());
registry.register(new BashTool() / PowerShellTool());  // 根据操作系统
registry.register(new GlobTool());
registry.register(new GrepTool());
registry.register(new CodeSearchTool());    // 延迟工具（shouldDefer = true）
registry.register(new MemorySearchTool());  // 延迟工具
registry.register(new PlanTools...());
```

系统启动时创建 ToolRegistry，将所有工具实例注册进 ConcurrentHashMap。延迟工具（CodeSearch、MemorySearch）也注册了，但 `shouldDefer()` 返回 true，不会出现在默认工具列表中。

### 阶段 2：每轮循环生成工具列表（Per Loop Iteration）

```java
// Agent.agentLoop() 每次迭代开始
var toolSchemas = registry.getAllSchemas(protocol);
  ↓
传给 LLM API（Anthropic 或 OpenAI 格式）
```

每轮 Agent Loop 开始时，调用 `getAllSchemas()` 生成当前可用工具的 JSON Schema 列表：
- **跳过延迟工具**：shouldDefer() = true 且未被发现的工具不包含
- **协议适配**：根据 protocol 参数转换为 Anthropic 或 OpenAI 格式
- **工具过滤**：如果设置了 toolNameFilter（如计划模式），进一步过滤

### 阶段 3：LLM 决策调用工具（LLM Decision）

```
LLM 收到工具列表 → 分析用户请求 → 决定调用哪些工具
  ↓
返回消息包含 tool_use blocks:
[
  {id: "tc_001", name: "ReadFile", args: {file_path: "main.py"}},
  {id: "tc_002", name: "EditFile", args: {file_path: "main.py", old_string: "...", new_string: "..."}}
]
```

### 阶段 4：工具执行与审批（Tool Execution）

```java
// Agent.agentLoop() 收到 LLM 响应
解析 tool_use blocks
  ↓
var executor = new StreamingExecutor(registry, checker, hookEngine, ...);
var results = executor.executeAll(toolCallInfos);
  ↓
对每个工具：
  1. 查找工具：registry.get(toolName)
  2. 准备预览：MutationPreview.prepare() [WriteFile/EditFile]
  3. 权限检查：checker.check(tool, args)
     ├─ 第一级：会话缓存（allowAlwaysRules）
     ├─ 第二级：模式决策（DEFAULT/ACCEPT_EDITS/BYPASS）
     └─ 第三级：自定义规则
  4. 决策处理：
     ├─ DENY → 返回错误
     ├─ ALLOW → 跳到步骤 7
     └─ ASK → 进入审批流程（步骤 5-6）
  5. 异步审批：
     - 发送 PermissionRequestEvent（包含 diff）
     - 阻塞等待用户响应（最多 5 分钟）
  6. 处理响应：
     ├─ DENY → 返回错误
     ├─ ALLOW → 继续
     └─ ALLOW_ALWAYS → 添加缓存规则 + 继续
  7. TOCTOU 验证：preview.verifyCurrent() [验证文件未被修改]
  8. Hook 检查：hookEngine.runPreToolHooks()
  9. 执行工具：tool.execute(args)
  10. 记录日志：ledger.append(record)
  11. 返回结果：ToolExecResult
```

### 阶段 5：结果返回与下一轮（Result Feedback）

```java
var resultBlocks = results.stream()
    .map(r -> new ToolResultBlock(r.toolId(), r.output(), r.isError()))
    .toList();
conv.addToolResultsMessage(resultBlocks);
  ↓
继续下一轮 Agent Loop，将工具结果传回 LLM
  ↓
LLM 分析结果，决定下一步：继续调用工具 or 返回最终答案
```

### 特殊流程：延迟工具发现

```
LLM 需要某个延迟工具（如 CodeSearch）
  ↓
调用 ToolSearch(query="select:CodeSearch")
  ↓
ToolSearchTool.execute():
  - registry.findDeferredByNames(["CodeSearch"])
  - registry.markDiscovered("CodeSearch")
  ↓
下一轮 getAllSchemas() 会包含 CodeSearch
  ↓
LLM 现在可以调用 CodeSearch
```

## 第一部分：核心抽象
### 1.1 Tool 接口：统一的工具契约

```java
// com/mewcode/tool/Tool.java
package com.mewcode.tool;
import java.util.Map;
public interface Tool {
    String name();
    String description();
    ToolCategory category();
    ToolEffect effect();
    Map<String, Object> schema();
    ToolResult execute(Map<String, Object> args);
    default boolean shouldDefer() {
        return false;
    }
}
```

Tool 接口是工具系统的核心抽象，定义了统一的工具契约。任何想要注册到 ToolRegistry、被 LLM 调用的功能都必须实现这个接口。它解决了三个问题：

1. **标准化接口**：所有工具用同样的方式描述自己（name、description、schema）
2. **统一执行**：StreamingExecutor 通过 `execute(args)` 调用任何工具，不关心具体实现
3. **类型安全**：通过 category 和 effect 标记工具特性，执行引擎据此做并发控制和日志记录

工具必须实现的方法：

- `name()` - 工具标识符，传给 LLM API
- `description()` - 使用说明，LLM 根据此决定何时调用
- `category()` - 分类：READ / WRITE / COMMAND
- `effect()` - 副作用标记，比 category 更细粒度
- `schema()` - JSON Schema 格式的参数定义
- `execute(args)` - 执行逻辑，接收参数 Map 返回 ToolResult
- `shouldDefer()` - default 方法，延迟加载标记（默认 false）

effect() 有默认实现，从 category 推导副作用：

```java
// com/mewcode/tool/Tool.java
default ToolEffect effect() {
    return switch (category()) {
        case READ -> ToolEffect.READ_ONLY_LOCAL;
        case WRITE -> ToolEffect.MUTATION;
        case COMMAND -> ToolEffect.PROCESS;
    };
}
```

这个方法使用 switch 表达式自动映射，工具可以覆盖返回更精确的类型（如 USER_INTERACTION）。
### 1.2 ToolCategory：三种工具分类

```java
// com/mewcode/tool/ToolCategory.java
package com.mewcode.tool;
public enum ToolCategory {
    READ, WRITE, COMMAND
}
```

ToolCategory 将工具分为三类，用于并发控制和权限决策：

- **READ** - 只读操作（读文件、搜索内容），可以并行执行
- **WRITE** - 写入操作（修改文件、创建目录），必须串行执行
- **COMMAND** - 外部命令（Bash、PowerShell），必须串行执行

这个分类在执行引擎中决定并发策略：


```java
// com/mewcode/agent/StreamingExecutor.java (第 100-112 行)
private List<ToolBatch> partitionToolCalls(List<ToolCallInfo> calls) {
    var batches = new ArrayList<ToolBatch>();
    for (var call : calls) {
        var tool = registry.get(call.toolName());
        boolean safe = tool != null && tool.category() == ToolCategory.READ;
        if (safe && !batches.isEmpty() && batches.getLast().concurrent()) {
            batches.getLast().calls().add(call);
        } else {
            batches.add(new ToolBatch(safe, new ArrayList<>(List.of(call))));
        }
    }
    return batches;
}
```

partitionToolCalls() 将工具调用分批：连续的 READ 工具分到一组并行执行，WRITE 和 COMMAND 工具各占一批串行执行。这样既提高了只读操作的效率，又避免了写入冲突和命令执行的竞态条件。
### 1.3 ToolEffect：细粒度副作用

```java
// com/mewcode/tool/ToolEffect.java
package com.mewcode.tool;
public enum ToolEffect {
    READ_ONLY_LOCAL,
    READ_ONLY_EXTERNAL,
    USER_INTERACTION,
    MUTATION,
    PROCESS,
    EXTERNAL_EFFECT;
    public boolean sideEffect() {
        return this == MUTATION ||
               this == PROCESS ||
               this == EXTERNAL_EFFECT;
    }
}
```

ToolEffect 提供比 ToolCategory 更细的区分。READ_ONLY_LOCAL 表示读取本地文件，READ_ONLY_EXTERNAL 表示查询外部 API，USER_INTERACTION 表示需要用户输入（如 AskUserTool），MUTATION 表示修改文件系统，PROCESS 表示执行外部进程，EXTERNAL_EFFECT 表示对外部系统的副作用（如发送邮件、修改数据库）。
sideEffect() 方法返回该效果是否有副作用。在执行日志记录中使用：


```java
// com/mewcode/agent/StreamingExecutor.java (第 192 行)
if (tool.effect().sideEffect()) {
    record(call, tool, ToolExecutionRecord.Status.PENDING, argsHash, preview, "");
}
```

这段代码在工具执行前检查是否有副作用。只有有副作用的工具调用才会被记录到 JsonlToolExecutionLedger，用于审计追踪和崩溃恢复。纯读取操作不记录，减少日志体积。
### 1.4 ToolResult：统一返回类型

```java
// com/mewcode/tool/ToolResult.java
package com.mewcode.tool;
public record ToolResult(String output, boolean isError) {
    public static ToolResult success(String output) {
        return new ToolResult(output, false);
    }
    public static ToolResult error(String message) {
        return new ToolResult(message, true);
    }
}
```

Java 16 的 record 类型自动生成构造函数、getter、equals、hashCode 和 toString。ToolResult 包含两个字段：output 是工具的输出文本，isError 标记是否为错误。
两个静态工厂方法让调用方的意图更清晰：


```java
// com/mewcode/tool/impl/ReadFileTool.java (第 71-74 行)
String filePath = stringArg(args, "file_path", "");
if (filePath.isEmpty()) {
    return ToolResult.error("Error: file_path is required");
}
```

这是 ReadFileTool.execute() 方法的开头。从参数 Map 中提取 file_path，如果为空直接返回 ToolResult.error()。所有工具实现遵循同样的模式：参数验证失败返回 error，执行失败返回 error，成功返回 success。
### 1.5 ToolRegistry：注册中心


```java
// com/mewcode/tool/ToolRegistry.java (第 10-27 行)
public class ToolRegistry {
    public static final int MAX_OUTPUT_CHARS = 10_000;
    private final Map<String, Tool> tools = new ConcurrentHashMap<>();
    private final Set<String> discoveredTools = ConcurrentHashMap.newKeySet();
    public void register(Tool tool) {
        tools.put(tool.name(), tool);
    }
    public Tool get(String name) {
        return tools.get(name);
    }
    public void markDiscovered(String name) {
        discoveredTools.add(name);
    }
    public boolean isDiscovered(String name) {
        return discoveredTools.contains(name);
    }
}
```

ToolRegistry 用 ConcurrentHashMap 存储工具，保证线程安全。tools 存储所有已注册的工具，discoveredTools 存储已被 ToolSearch 发现的延迟工具。
register() 方法将工具放入 Map，get() 根据名称查找工具。这两个方法在整个系统中被频繁调用：Agent 在启动时调用 register() 注册工具，StreamingExecutor 在执行时调用 get() 查找工具。
### 1.6 getAllSchemas：生成 LLM 工具列表


```java
// com/mewcode/tool/ToolRegistry.java (第 35-54 行)
public List<Map<String, Object>> getAllSchemas(String protocol) {
    var schemas = new ArrayList<Map<String, Object>>();
    for (var tool : tools.values()) {
        if (tool.shouldDefer() && !discoveredTools.contains(tool.name())) {
            continue;
        }
        var base = tool.schema();
        if (isOpenAIProtocol(protocol)) {
            schemas.add(Map.of(
                    "type", "function",
                    "name", base.get("name"),
                    "description", base.get("description"),
                    "parameters", base.get("input_schema")
            ));
        } else {
            schemas.add(base);
        }
    }
    return schemas;
}
```

这个方法在每轮 Agent Loop 开始时被调用，生成当前可用工具的 schema 列表传给 LLM API。它遍历所有已注册工具，跳过那些 shouldDefer() 返回 true 但尚未被发现的延迟工具。
对于保留的工具，根据 protocol 参数适配两种格式。OpenAI 协议要求外层包一个 type: function 字段，参数定义放在 parameters 字段。Anthropic 协议直接使用工具的 schema，参数定义在 input_schema 字段。
调用方代码：


```java
// com/mewcode/agent/Agent.java (第 175-185 行)
var iterToolSchemas = registry.getAllSchemas(protocol);
if (toolNameFilter != null) {
    iterToolSchemas = iterToolSchemas.stream()
            .filter(schema -> {
                Object name = schema.get("name");
                return name == null || toolNameFilter.test(name.toString());
            })
            .toList();
}
```

这段代码在 Agent.agentLoop() 方法中。每次迭代开始时调用 getAllSchemas(protocol) 获取当前工具列表。如果设置了 toolNameFilter（计划模式或特定权限模式），还会进一步过滤只保留允许的工具。
### 1.7 createDefault：默认工具注册


```java
// com/mewcode/tool/ToolRegistry.java (第 120-143 行)
public static ToolRegistry createDefault() {
    var reg = new ToolRegistry();
    reg.register(new ReadFileTool());
    reg.register(new WriteFileTool());
    reg.register(new EditFileTool());
    String os = System.getProperty("os.name").toLowerCase();
    if (os.contains("win")) {
        reg.register(new PowerShellTool());
    } else {
        reg.register(new BashTool());
    }
    reg.register(new GlobTool());
    reg.register(new GrepTool());
    reg.register(new CodeSearchTool(Path.of(System.getProperty("user.dir"))));
    reg.register(new MemorySearchTool(Path.of(System.getProperty("user.dir"))));
    var plans = new PlanCoordinator(new PlanRepository(Path.of(System.getProperty("user.dir"))));
    reg.register(new PlanTools.Create(plans));
    reg.register(new PlanTools.Complete(plans));
    reg.register(new PlanTools.Fail(plans));
    return reg;
}
```

这是工具系统的启动入口。方法创建一个新的 ToolRegistry，依次注册 10 个默认工具：ReadFile、WriteFile、EditFile 是文件操作工具，Bash 或 PowerShell 根据操作系统选择，Glob 和 Grep 是搜索工具，CodeSearch 和 MemorySearch 是 RAG 和记忆工具，三个 PlanTools 用于任务规划。
调用方在 Agent 初始化时：


```java
// com/mewcode/agent/Agent.java (第 77-78 行)
ToolRegistry registry = ToolRegistry.createDefault();
var executor = new StreamingExecutor(registry, checker, hookEngine, eventQueue, recoveryState);
```

Agent 构造函数调用 createDefault() 创建注册中心，然后传给 StreamingExecutor 用于工具执行。
## 第二部分：安全机制

安全机制层包含 5 个组件，防止 AI 误操作导致数据损坏或安全问题。

### 2.1 FileStateCache：Read-before-edit 强制

FileStateCache 防止 AI 在未读取文件的情况下盲目修改。它用 ConcurrentHashMap 缓存已读文件的内容和修改时间，WriteFileTool 和 EditFileTool 执行前必须通过 validate() 检查。检查两个条件：文件是否已被 ReadFileTool 读取，文件修改时间是否晚于缓存记录（检测外部修改）。

```java
// ReadFileTool 读取后记录
fileStateCache.record(path, content, mtime);

// WriteFileTool 写入前验证
String err = fileStateCache.validate(path);
if (err != null) return ToolResult.error(err);
```

### 2.2 AtomicFileWriter：原子写入

AtomicFileWriter 防止写入过程中崩溃导致文件损坏。实现方式是先写入临时文件（.minicode-*.tmp），然后用原子操作移动到目标位置。如果系统支持 ATOMIC_MOVE 就用原子移动，不支持就降级为普通移动。无论成功失败，finally 块都会清理临时文件。

```java
Path temp = Files.createTempFile(parent, ".minicode-", ".tmp");
Files.writeString(temp, content);
Files.move(temp, target, StandardCopyOption.ATOMIC_MOVE);
```

### 2.3 MutationPreview：修改预览与 TOCTOU 验证

MutationPreview 用于权限审批流程，包含修改前后的内容、diff 和哈希值。prepare() 在审批前生成预览，verifyCurrent() 在审批通过后、执行前验证文件未被篡改。验证方式是重新计算文件和 diff 的 SHA-256 哈希，与审批时的哈希比较，不匹配就抛出 ConcurrentModificationException。这防止了 TOCTOU 攻击（审批后执行前的时间窗口被利用）。

```java
// 审批前生成预览
MutationPreview preview = MutationPreview.prepare(toolName, args);

// 执行前验证
preview.verifyCurrent();  // 哈希不匹配会抛异常
```

### 2.4 JsonlToolExecutionLedger：执行日志

JsonlToolExecutionLedger 以 JSONL 格式记录所有有副作用的工具执行，用于审计追踪和崩溃恢复。日志存储在 `.mewcode/sessions/{sessionId}/tool-ledger.jsonl`，每行一个 JSON 对象。构造函数加载时会将上次崩溃留下的 PENDING 记录标记为 UNKNOWN。append() 方法是同步的，保证并发写入安全。

```java
// 执行前记录 PENDING
record(call, tool, Status.PENDING, argsHash, preview, "");

// 执行后记录 COMPLETED 或 FAILED
record(call, tool, result.isError() ? Status.FAILED : Status.COMPLETED, ...);
```

### 2.5 ToolExecutionRecord：执行记录

ToolExecutionRecord 是 record 类型，包含工具调用的完整信息：toolCallId（唯一标识）、toolName、effect（副作用类型）、status（5 种状态：PENDING / AWAITING_APPROVAL / COMPLETED / FAILED / UNKNOWN）、argsHash（参数哈希）、beforeHash/afterHash/diffHash（来自 MutationPreview）、result（执行结果）、runId（运行实例 ID）、updatedAt（更新时间）。

第三部分：权限审批
### 3.1 PermissionMode：审批策略

```java
// com/mewcode/permission/PermissionMode.java
package com.mewcode.permission;
import com.mewcode.tool.ToolCategory;
public enum PermissionMode {
    DEFAULT,
    ACCEPT_EDITS,
    PLAN,
    BYPASS;
    public Decision decide(ToolCategory category) {
        return switch (this) {
            case DEFAULT -> switch (category) {
                case READ -> Decision.ALLOW;
                case WRITE, COMMAND -> Decision.ASK;
            };
            case ACCEPT_EDITS -> switch (category) {
                case READ, WRITE -> Decision.ALLOW;
                case COMMAND -> Decision.ASK;
            };
            case PLAN -> DEFAULT.decide(category);
            case BYPASS -> Decision.ALLOW;
        };
    }
    public enum Decision {
        ALLOW, DENY, ASK
    }
}
```

PermissionMode 定义了 4 种审批模式。DEFAULT 模式下，READ 工具自动允许，WRITE 和 COMMAND 需要询问。ACCEPT_EDITS 模式下，READ 和 WRITE 都自动允许，只有 COMMAND 需要询问。PLAN 模式委托给 DEFAULT。BYPASS 模式下所有工具都自动允许。
decide() 方法接收 ToolCategory，返回 Decision。Decision 枚举有三个值：ALLOW 表示直接允许，DENY 表示直接拒绝，ASK 表示需要询问用户。
这个方法被 PermissionChecker 调用：


```java
// com/mewcode/permission/PermissionChecker.java (第 90-91 行)

```

PermissionChecker.check() 方法先从模式获取默认决策，然后应用自定义规则可能覆盖这个决策。

### 3.2 完整审批流程

工具的审批流程贯穿整个执行生命周期，从决策、预览、异步等待到最终执行。完整的调用链路是：

```
Agent.agentLoop()                          // Agent Loop 主循环
  ↓
LLM API 返回消息，解析出 tool_use blocks
  ↓
创建 StreamingExecutor 实例
  ↓
executor.executeAll(callInfos)             // 执行所有工具调用
  ↓
partitionToolCalls(calls)                  // 分批：只读并行，写入/命令串行
  ↓
for each batch:
  if (并行批次) → 虚拟线程池并行执行
  else → 串行执行
    ↓
  executeSingle(call)                      // 单个工具的完整执行流程
    ↓
  返回 ToolExecResult
  ↓
收集所有结果，封装成 ToolResultBlock
  ↓
conv.addToolResultsMessage(resultBlocks)   // 添加到对话历史
  ↓
继续下一轮 Agent Loop
```

关键代码在 Agent.agentLoop() 中：

```java
// com/mewcode/agent/Agent.java (第 436-441 行)
// Execute tool calls
var executor = new StreamingExecutor(registry, checker, hookEngine, queue, 
                                      recoveryState, workDir, sessionId);
var callInfos = toolCalls.stream()
        .map(tc -> new ToolCallInfo(tc.toolId, tc.toolName, tc.args))
        .toList();
var results = executor.executeAll(callInfos);
```

每次 LLM 返回工具调用时，Agent Loop 都会创建新的 StreamingExecutor 实例（每次执行有独立的 runId），将工具调用转换为 ToolCallInfo 列表，调用 executeAll() 批量执行。

#### 3.2.1 流程入口：executeSingle()


#### 3.2.2 权限决策：三级检查

executeSingle() 在准备好修改预览后，进入权限检查阶段。这是工具执行前的关键安全卡口，决定工具是否可以执行。

```java
// com/mewcode/agent/StreamingExecutor.java (第 129-140 行)
if (checker != null) {
    var check = checker.check(tool, call.args());
    
    switch (check.decision()) {
        case DENY -> {
            String msg = "Permission denied: " + check.reason();
            putSafe(new AgentEvent.ToolResultEvent(
                call.toolId(), call.toolName(), msg, true, 0));
            return new ToolExecResult(call.toolId(), msg, true);
        }
        
        case ASK -> {
            // 进入异步审批流程
        }
        
        case ALLOW -> {
            // 直接执行
        }
    }
}
```

**这段代码的作用**：

调用 PermissionChecker.check() 进行三级决策（会话缓存 → 模式决策 → 自定义规则），返回 DENY / ASK / ALLOW 三种结果之一。根据结果分别处理：

- **DENY**：直接拒绝，返回错误。适用于被自定义规则禁止的操作（如删除关键文件）
- **ASK**：进入异步审批流程，弹出对话框等待用户选择
- **ALLOW**：跳过审批，直接执行工具

这是整个工具执行流程的第一道防线，后续还有 TOCTOU 验证和 Hook 检查作为额外防护。

StreamingExecutor 调用 PermissionChecker 进行决策：


PermissionChecker.check() 实现三级决策机制，按优先级从高到低依次检查：

```java
// com/mewcode/permission/PermissionChecker.java (第 82-100 行)
public CheckResult check(Tool tool, Map<String, Object> args) {
    // 第一级：检查会话级"总是允许"缓存
    String content = extractContent(tool.name(), args);
    if (content != null && allowAlwaysRules.contains(tool.name() + ":" + content.hashCode())) {
        return new CheckResult(Decision.ALLOW, "allowed by session rule");
    }

    // 第二级：从模式获取默认决策
    Decision decision = mode.decide(tool.category());

    // 第三级：应用自定义规则
    for (var rule : rules) {
        if (rule.matches(tool.name(), args)) {
            decision = rule.decision();
            break;
        }
    }

    return new CheckResult(decision, "");
}
```

**第一级：会话缓存（最高优先级）**

extractContent() 从工具参数中提取关键内容：

```java
// com/mewcode/permission/PermissionChecker.java
private String extractContent(String toolName, Map<String, Object> args) {
    return switch (toolName) {
        case "WriteFile", "EditFile", "ReadFile" -> 
            stringArg(args, "file_path", null);
        case "Bash", "PowerShell" -> 
            stringArg(args, "command", null);
        default -> null;
    };
}
```

对于文件操作工具，content 是文件路径；对于命令工具，content 是命令文本。缓存的 key 是 `toolName:contentHashCode`。

如果用户之前对同样的操作选择了"Always Allow"，这次就直接返回 ALLOW，跳过后续检查。这是最快的路径，避免重复询问。

**第二级：模式决策（默认策略）**

如果缓存未命中，从 PermissionMode 获取默认决策：

```java
// com/mewcode/permission/PermissionMode.java
public Decision decide(ToolCategory category) {
    return switch (this) {
        case DEFAULT -> switch (category) {
            case READ -> Decision.ALLOW;        // 读取自动允许
            case WRITE, COMMAND -> Decision.ASK; // 写入和命令需询问
        };
        case ACCEPT_EDITS -> switch (category) {
            case READ, WRITE -> Decision.ALLOW;  // 读写自动允许
            case COMMAND -> Decision.ASK;        // 只有命令需询问
        };
        case PLAN -> DEFAULT.decide(category);   // 委托给 DEFAULT
        case BYPASS -> Decision.ALLOW;           // 全部自动允许
    };
}
```

模式通过 config.yaml 配置：

```yaml
# DEFAULT 模式（推荐）
permission_mode: sandbox

# ACCEPT_EDITS 模式（快速开发）
permission_mode: accept_edits

# BYPASS 模式（危险，仅测试用）
permission_mode: auto
```

不同模式对应不同的使用场景：
- DEFAULT：日常使用，读取自动允许，写入和命令需要审批
- ACCEPT_EDITS：快速开发，只有执行外部命令需要审批
- PLAN：规划模式，行为同 DEFAULT
- BYPASS：测试环境，所有操作自动允许

**第三级：自定义规则（最低优先级但可覆盖）**

自定义规则从 YAML 文件加载，可以覆盖模式的默认决策：

```java
// com/mewcode/permission/PermissionChecker.java
for (var rule : rules) {
    if (rule.matches(tool.name(), args)) {
        decision = rule.decision();  // 覆盖模式决策
        break;
    }
}
```

规则示例（在 .mewcode/permissions.yaml 中）：

```yaml
rules:
  # 允许读取特定目录
  - tool: ReadFile
    path_pattern: "src/**/*.java"
    decision: ALLOW
    
  # 拒绝删除关键文件
  - tool: Bash
    command_pattern: ".*rm.*config\\.yaml.*"
    decision: DENY
    
  # 询问所有数据库操作
  - tool: Bash
    command_pattern: ".*psql.*"
    decision: ASK
```

规则匹配按顺序进行，第一个匹配的规则决定最终决策。规则可以让某些原本需要审批的操作自动允许，也可以让某些原本自动允许的操作强制审批。

**决策流程总结**

```
工具调用
    ↓
第一级：allowAlwaysRules 缓存
    ↓ 未命中
第二级：mode.decide(category)
    ↓ 返回默认决策
第三级：应用自定义规则（可能覆盖）
    ↓
返回最终决策：ALLOW / ASK / DENY
```

决策结果分三种：
- **DENY**：直接拒绝，记录错误，返回
- **ALLOW**：跳过审批，直接执行
- **ASK**：进入异步审批流程（下一小节）

#### 3.2.3 异步审批流程

当决策为 ASK 时，执行异步审批：

#### 3.2.5 TOCTOU 验证

审批通过后，执行前还有一次 TOCTOU 验证：

```java
// com/mewcode/agent/StreamingExecutor.java (第 169-177 行)

    try {
        preview.verifyCurrent();
    } catch (Exception stale) {
        if (tool.effect().sideEffect()) {
            record(call, tool, ToolExecutionRecord.Status.FAILED, 
                argsHash, preview, stale.getMessage());

```

verifyCurrent() 重新读取文件，计算哈希，与审批时的哈希比较。如果不匹配，说明文件在审批通过后被外部修改，抛出 ConcurrentModificationException。这防止了时间窗口攻击：恶意进程在审批通过后、执行前修改文件。

```java
    public FileVisitResult preVisitDirectory(Path dir, BasicFileAttributes attrs) {

            }
        }
        return FileVisitResult.CONTINUE;
```

```java
        if (batch.concurrent && batch.calls.size() > 1) {
            try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
                var futures = batch.calls.stream()
                        .map(call -> executor.submit(() -> executeSingle(call)))
                        .toList();
                for (var future : futures) {

                    } catch (Exception ignored) {}
                }
            }

            for (var call : batch.calls) {
                results.add(executeSingle(call));
            }
        }
    }
    return results;
}
```

### 5.2 partitionToolCalls：分批策略

partitionToolCalls() 是并发控制的核心，它将工具调用列表分成多个批次，决定哪些可以并行、哪些必须串行。

```java
// com/mewcode/agent/StreamingExecutor.java (第 100-112 行)
private List<ToolBatch> partitionToolCalls(List<ToolCallInfo> calls) {
    var batches = new ArrayList<ToolBatch>();
    for (var call : calls) {
        var tool = registry.get(call.toolName());
        boolean safe = tool != null && tool.category() == ToolCategory.READ;
        if (safe && !batches.isEmpty() && batches.getLast().concurrent()) {
            batches.getLast().calls().add(call);
        } else {
            batches.add(new ToolBatch(safe, new ArrayList<>(List.of(call))));
        }
    }
    return batches;
}
```

**分批逻辑**：

1. **查找工具类型**：从 registry 获取工具，检查 `tool.category()` 是否为 READ
2. **判断是否安全**：`safe = true` 表示只读工具，可以并行
3. **分批决策**：
   - 如果是只读工具 **且** 上一个批次也是并行批次 → 追加到同一批次
   - 否则 → 创建新批次（写入和命令工具总是独占一个批次）

**分批示例**：

```java
// 输入：5 个工具调用
[
  ReadFile("a.txt"),    // READ
  ReadFile("b.txt"),    // READ
  WriteFile("c.txt"),   // WRITE
  ReadFile("d.txt"),    // READ
  Bash("ls")            // COMMAND
]

// 输出：4 个批次
[
  Batch(concurrent=true,  calls=[ReadFile("a.txt"), ReadFile("b.txt")]),  // 批次1：并行
  Batch(concurrent=false, calls=[WriteFile("c.txt")]),                    // 批次2：串行
  Batch(concurrent=false, calls=[ReadFile("d.txt")]),                     // 批次3：串行（前面被打断）
  Batch(concurrent=false, calls=[Bash("ls")])                             // 批次4：串行
]
```

**为什么这样设计**：

- **只读工具并行**：多个 ReadFile 互不影响，可以同时执行，提高效率
- **写入工具串行**：WriteFile 可能修改同一文件，必须按顺序执行避免冲突
- **命令工具串行**：Bash/PowerShell 可能有副作用或依赖顺序，必须串行
- **打断规则**：一旦遇到写入或命令工具，后续的只读工具也不能合并到前面的并行批次（因为可能依赖前面的写入结果）

**ToolBatch 结构**：

```java
record ToolBatch(boolean concurrent, List<ToolCallInfo> calls) {}
```

- `concurrent` - 是否可以并行执行
- `calls` - 该批次包含的工具调用列表

```java
if (checker != null) {
    var check = checker.check(tool, call.args());
    switch (check.decision()) {
        case DENY -> {
            String msg = "Permission denied: " + check.reason();
            putSafe(new AgentEvent.ToolResultEvent(
                call.toolId(), call.toolName(), msg, true, 0));
            return new ToolExecResult(call.toolId(), msg, true);
        }
        case ASK -> {
            if (tool.effect().sideEffect()) {
                record(call, tool, ToolExecutionRecord.Status.AWAITING_APPROVAL,
                    argsHash, preview, "");
            }
            var future = new CompletableFuture<PermissionResponse>();
            String desc = checker.describeToolAction(call.toolName(), call.args());
            if (preview != null) {
                desc += "\n\n" + preview.diff()
                     + "\nbefore=" + preview.beforeHash().substring(0, 12)
                     + " diff=" + preview.diffHash().substring(0, 12);
            }
            putSafe(new AgentEvent.PermissionRequestEvent(call.toolName(), desc, future));
            PermissionResponse response;
            try {
                response = future.get(5, TimeUnit.MINUTES);
            } catch (Exception e) {
                response = PermissionResponse.DENY;
            }
            if (response == PermissionResponse.DENY) {
                if (tool.effect().sideEffect()) {
                    record(call, tool, ToolExecutionRecord.Status.FAILED,
                        argsHash, preview, "User denied permission");
                }
                putSafe(new AgentEvent.ToolResultEvent(
                    call.toolId(), call.toolName(),
                    "Permission denied by user", true, 0));
                return new ToolExecResult(call.toolId(),
                    "User denied permission", true);
            }
            if (response == PermissionResponse.ALLOW_ALWAYS) {
                String content = extractContent(call.toolName(), call.args());
                if (content != null) {
                    checker.addAllowAlwaysRule(call.toolName(), content);
                }
            }
        }
        case ALLOW -> {}
    }
}
```

如果 checker 存在，调用 check() 获取决策。根据决策类型处理：DENY 直接返回错误。ASK 记录 AWAITING_APPROVAL 状态，创建 CompletableFuture，生成描述（包含 diff），发送 PermissionRequestEvent，阻塞等待响应（最多 5 分钟）。如果响应是 DENY，记录 FAILED 状态并返回错误。如果响应是 ALLOW_ALWAYS，添加缓存规则。ALLOW 不做处理，继续执行。

## 小结
工具系统的实现展示了几个核心设计：
类型安全的抽象：Tool 接口用 Java 的类型系统约束所有工具，ToolCategory 和 ToolEffect 用枚举保证分类安全，ToolResult 用 record 保证不可变性。
分层安全机制：FileStateCache 强制 Read-before-edit，AtomicFileWriter 防止文件损坏，MutationPreview 防止 TOCTOU 攻击，JsonlToolExecutionLedger 提供审计追踪。
异步权限审批：PermissionChecker 实现三级决策（模式 + 规则 + 缓存），StreamingExecutor 用 CompletableFuture 实现非阻塞审批流程，PermissionResponse 提供三种响应类型。
智能并发执行：根据 ToolCategory 自动分批，只读工具并行执行用虚拟线程池，写入和命令工具串行执行保证安全。
协议适配：ToolRegistry.getAllSchemas() 根据 protocol 参数适配 Anthropic 和 OpenAI 两种格式，工具实现不感知协议差异。
延迟加载：Tool.shouldDefer() 默认方法让大多数工具继承 false，ToolSearchTool 实现按需发现，ToolRegistry.markDiscovered() 实现状态追踪。
代码总量约 2000 行，覆盖注册、发现、审批、执行、日志、安全六个维度，形成完整的工具运行时。
