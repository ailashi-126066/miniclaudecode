## 已完成的改进

### 1. 异常分类体系 ✅

**文件**: `src/main/java/com/mewcode/llm/LlmException.java`

实现了完整的语义化异常层次结构：

```java
LlmException (基类)
├── AuthenticationException      // 401/403 认证错误
├── RateLimitException           // 429 限流错误（含 Retry-After）
├── ContextTooLongException      // 413/上下文过长
└── NetworkException             // IOException/超时错误
```

**关键特性**：

- **自动分类**: `LlmException.classify(Throwable)` 方法将底层异常转换为语义化类型
- **HTTP 状态码识别**: 支持 401、403、413、429 等状态码
- **文本模式匹配**: 识别 "prompt is too long"、"context window" 等关键词
- **LangChain4j 集成**: 自动识别 LangChain4j 的异常类型
- **Retry-After 提取**: 从 429 响应中解析重试延迟

**测试覆盖**: 11 个单元测试（`LlmExceptionTest.java`）

### 2. 流式事件传递 ✅

**文件**: `src/main/java/com/mewcode/llm/StreamEvent.java`

`StreamEvent.Error` 现在保留完整的类型化异常对象：

```java
record Error(LlmException exception) implements StreamEvent {
    // 兼容构造函数
    public Error(String message) {
        this(new LlmException(message));
    }
    
    // 兼容方法
    public String message() {
        return exception.getMessage();
    }
}
```

**优势**：

- Agent 不再依赖字符串匹配（如 `message.contains("rate limit")`）
- 使用 `instanceof` 进行类型安全的错误判断
- 保持向后兼容性（支持字符串构造函数和 `message()` 方法）

### 4. Agent 恢复策略 ✅

**文件**: `src/main/java/com/mewcode/agent/Agent.java`

实现了完整的错误恢复逻辑：

#### 4.1 上下文过长恢复

```java
if (error instanceof LlmException.ContextTooLongException) {
    if (contextRetries < 3) {
        contextRetries++;
        // 应用 tool-result budget
        // 强制压缩上下文
        // 重新注入长期记忆
        continue;  // 重试
    }
}
```

**策略**：
- 最多重试 3 次
- 先裁剪工具结果
- 执行上下文压缩
- 重新发起 LLM 请求

#### 4.2 限流恢复

```java
if (error instanceof LlmException.RateLimitException rateLimit
        && rateLimitRetries < 3) {
    rateLimitRetries++;
    long waitMs = retryDelayMillis(
            rateLimit.getRetryAfter(), rateLimitRetries);
    putSafe(queue, new AgentEvent.RetryEvent(
            "Rate limited, retrying...", waitMs));
    Thread.sleep(waitMs);
    continue;  // 重试
}
```

**策略**：
- 最多重试 3 次
- **优先使用 Retry-After** 响应头（如果可用）
- 否则使用**指数退避**：1秒、2秒、4秒、8秒...最大 64 秒

**指数退避算法**：

```java
private static long retryDelayMillis(String retryAfter, int attempt) {
    if (retryAfter != null && !retryAfter.isBlank()) {
        long seconds = Long.parseLong(retryAfter.trim());
        return Math.min(seconds * 1000L, 120_000L);
    }
    // 指数退避: 1s << (attempt-1)，最大移位 6 (64s)
    long backoff = 1_000L << Math.min(Math.max(attempt - 1, 0), 6);
    return Math.min(backoff, 120_000L);
}
```

#### 4.3 认证错误（不重试）

```java
// Authentication and unknown errors are not safe to retry.
break;
```

**策略**：
- 不自动重试
- 直接通知上层
- 提示用户检查 API Key、模型配置和环境变量

#### 4.4 网络错误（当前不重试）

**策略**：
- 当前版本不自动重试
- 已正确分类为 `NetworkException`
- 预留扩展点，未来可增加有限重试

## 架构优势

### 1. 类型安全

从字符串匹配升级到类型判断：

```java
// 旧方式（易出错）
if (error.message().contains("rate limit")) { ... }

// 新方式（类型安全）
if (error instanceof LlmException.RateLimitException rateLimit) {
    String retryAfter = rateLimit.getRetryAfter();
    ...
}
```

### 2. 分层解耦

```
底层 Provider 异常
    ↓
语义化 LlmException
    ↓
StreamEvent.Error
    ↓
Agent 按类型恢复
    ↓
TUI / Remote / Print 展示
```

### 3. 扩展性

新增 Provider 或错误类型时，只需：

1. 在 `LlmException.classify()` 中添加识别逻辑
2. Agent 的恢复策略自动生效
3. 无需修改上层 UI 代码

## 已知限制和未来改进

### 1. Retry-After 提取

**当前状态**: 从异常消息文本中解析 `Retry-After: 7`

**限制**: 
- LangChain4j 的 `HttpException` 主要暴露 `statusCode()`
- 不一定直接暴露完整的 HTTP 响应头

**改进方向**:
- 自定义 LangChain4j HttpClient
- 使用能暴露 response headers 的传输层

### 2. 网络错误重试

**当前状态**: 网络错误不自动重试

**改进方向**:
- 增加有限重试（2-3 次）
- 区分连接超时和服务端错误
- 使用指数退避策略

### 3. 部分下游消费者

**当前状态**: `ContextCompactor`、`MemoryManager` 等模块主要读取 `err.message()`

**改进方向**:
- 逐步迁移到 `err.exception()` 进行类型判断
- 实现更精细化的恢复策略

## 使用示例

### Agent 代码中的错误处理

```java
// 消费流事件
switch (event) {
    case StreamEvent.Error err -> {
        var exception = err.exception();
        
        // 类型安全的错误处理
        if (exception instanceof LlmException.ContextTooLongException) {
            // 自动压缩并重试
            forceCompact(conv);
            continue;
        }
        
        if (exception instanceof LlmException.RateLimitException rateLimit) {
            // 使用 Retry-After 或指数退避
            long waitMs = retryDelayMillis(
                rateLimit.getRetryAfter(), 
                rateLimitRetries
            );
            Thread.sleep(waitMs);
            continue;
        }
        
        // 认证错误和未知错误不重试
        break;
    }
}
```
