# 10　MCP 工具进入统一目录

MCP 负责远端工具发现和执行，工具搜索由公共 Tools 组件负责。当前只支持工具，不支持 resources、prompts 或 elicitation。

## 连接与发现

配置通过 MCPModule.open_session 校验后建立会话连接。FastMCP 处理 stdio/HTTP、协议和分页，LangChain 的原生工具转换将同一次发现快照变成可调用工具。目录和执行对象共享这一批定义，初次连接不再重复刷新列表。

## 主模型怎样找到远端工具

MCPRun.refresh 将启用的具体工具注册到公共工具目录。模型先看按 MCP 服务分类的名称和一句话用途，调用统一 ToolSearch 后，才在下一轮拿到对应的完整定义。随后直接调用 mcp__服务__工具。没有额外筛选模型，也没有 MCPCall 通用包装入口。

本地工具与 MCP 工具使用同一发现流程。配置使用 disabled_tools 列出禁止的远端工具；其余启用工具均按需披露。旧 loading/tool_modes 字段明确拒绝，不再保留 direct/dispatch 策略。



## 校验、执行和记录

完整定义已加载仍不等于允许执行。公共执行器先校验参数、只读约束与审批。MCP 在调用前重新获取远端定义，检查参数 schema 和权限标记是否变化；变化就拒绝执行，不能套用旧审批。这个执行前校验与发现阶段的去重是两件事。

## 框架和项目的职责

FastMCP 和 LangChain 负责协议、连接与原生工具转换；项目负责配置可信度、分支目录、公共 ToolSearch、权限、执行前定义核对和效果记录。
