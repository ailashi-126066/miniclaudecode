# 参考手册的写法与展示分析

这页记录本次具体参考了什么，以及怎样换成 pycode 的内容。参考目录是用户指定的 `gofeedvideo/docs/interview`；只读取其手册和网页，没有修改参考项目，也没有运行它的API、Worker或数据库。

## 先分析正文：参考的是怎样带人读完一件事

参考手册围绕账号、上传、Feed、通知等具体功能组织内容，先说明用户要完成什么，再跟着请求往下走。我们沿用这条思路，以“修复 parser.py 并运行测试”为连续例子，让前后章节在同一件事里相遇。

例如组装章先解释任务为什么还不能交给模型：项目位置、模型连接、历史和工具都还没准备好。会话准备好以后，Agent章再接着讲模型如何提出读取文件，Tools章解释为什么先检查再执行。这样读者知道每个模块是在解决前面哪一个缺口，不需要自己把互不相连的职责介绍拼起来。

参考页的函数卡片在原地展示完整函数、逐条说明和辅助函数。这里保留这些核对手段，同时让每一步的导读文字显示在折叠代码之前：先读“为什么调用、传什么、结果交给谁”，有疑问再展开。类名、字段名和框架名用于回到代码定位，不代替正文解释。

| 读者读到哪里 | 这里需要讲清什么 | pycode中的例子 |
|---|---|---|
| 一章开始 | 前面做到哪一步，现在还缺什么 | 文件已修好，现在想按review指令再检查 |
| 步骤之间 | 上一步的结果为何让下一步成为必要 | 找到Skill名称还不等于读过正文，必须实际读取 |
| 一个函数之前 | 由谁调用、为什么、传入什么 | launcher收到运行对象后才调用runtime.run |
| 一个函数之后 | 返回给谁，谁继续处理 | 图返回等待问题，会话保存，界面等用户回答 |
| 主线走完 | 回头解释设计、框架和组装 | 哪个框架方法负责循环，应用向它提供哪些能力 |
| 发生失败 | 能保留什么，哪些动作不能重试 | 保存过历史不等于新进程能继续旧执行图 |

表格和源码索引放在故事之后用于查找，不承担第一次讲解。不能照搬一套小节标题，然后每节孤立写几句；也不能把“框架→适配器→服务”当成已经解释了调用关系。

## 再分析网页的交互

实际打开了参考 `index.html`，切换到账号章节，并展开了 `Service.Register`。确认同一节点内部同时有中文逐条解释、完整Go函数和 `normalizeRegisterRequest` 等辅助节点；展开不会跳转另一页。另在源码浏览器验证了按文件路径筛选、选择 `Service.Register`，以及组成函数链接与带行号的完整函数展示。

| 交互 | 参考实现 | 本手册实现 |
|---|---|---|
| 左侧导航 | 固定侧栏、按模块名筛选、hash切章、当前项高亮 | 保留相同结构与浅色配色，标题换成pycode |
| 正文 | 白色内容卡、概念表、浅色text例子、深色代码块 | 同样的排版，主线改为连续的任务导读 |
| 调用入口/结果 | 顶部请求框、箭头、底部结果框 | CLI、框架事件或后台入口；结果指出持久化与返回边界 |
| 函数卡片 | 函数名、文件路径、职责；“展开＋/收起−” | 先显示中文动作与导读，再列Python方法和真实源行范围 |
| 原地展开 | 原生details/summary，无业务服务请求 | 相同浏览器原生机制，可键盘操作 |
| 辅助函数 | 父卡片内递归嵌套，保留当前位置 | 保留嵌套结构，不通过新tab打断阅读 |
| 并行入口 | groups显示分支，窄屏转单列 | 对独立入口和协作分支显式标注，避免假顺序 |
| 独立样页 | account.html只展示账号章 | run.html只展示Agent章，作为阅读样页 |
| 完整源码 | source.html按文件/声明选择，带源码行号和调用列表 | Python AST索引，保守显示可定位调用，动态注入另外解释 |
| 系统总图 | Mermaid描述经Graphviz在构建时变成SVG | 沿用构建期SVG与缩放，不依赖浏览器访问CDN |
| 离线能力 | HTML内嵌内容、CSS、JS，无须启动业务 | index/run/source均可离线阅读，不需要模型凭据 |

样式基于参考的account-chain.css和页面基础CSS适配，Python源码索引、章节、解释、模块链与运行时说明重新编写。没有把视频后端的业务内容复制成pycode能力。

## 数据和生成方式

参考项目把人写的内容与机器提取的源码分开：content模板保存叙述，chain JSON保存链节点解释，语法索引提供完整函数与位置，build/render输出Markdown与静态网页。

这里保留相同方式：

```text
content/*.md.in              人写的模块分析、例子、设计和边界
content/chains-*.json        人核对的业务链、节点说明、递归helpers
content/inline-*.json        人核对的数据/契约解释
Python AST                  真实完整源码、装饰器、方法和嵌套定义
build.py + render.cjs        同时输出Markdown与离线页面
coverage.json               源码版本、文件SHA、覆盖数量、生成输入/产物摘要
```

生成时会核对每个symbol真实存在，不会把手抄旧代码留在网页里。生成检查也不是语义审查：调用是否发生、是否通过工厂或框架触发，仍由读代码的作者和交叉审查核对。

## 为什么不能只替换项目名

参考是Go视频HTTP后端，pycode是Python本地Agent。直接替换名词会产生错误：

- pycode没有Gin Handler、视频业务SQL或Redis缓存，不能硬套“Handler→Service→Repo”。
- App组装是能力和生命周期连接，不等于每次请求都执行全部模块。
- LangGraph回调、SDK middleware、LangMem后台整理和MCP连接有不同触发点，不能画成普通同步函数依次调用。
- 会话会话 Store、模型请求SQLite、派生摘要、记忆JSON和Git快照保存的内容和用途各不相同，不能统一叫“数据库”。
- 平台沙箱、真实模型费用和不可恢复外部副作用要按当前实现说，不借参考项目的测试结论证明本项目。

因此，本手册沿用它的阅读与展示方式，内容以当前pycode源码为准，并为每个模块补上框架在这一步怎么用，以及应用怎样把各功能接起来的说明。
