# 15　TeamState、邮箱协作和 A→B 交接

主 Agent 把一个任务交给成员 A，A 在自己的工作区执行。任务、依赖和邮箱由 TeamState 统一管理；子任务内部仍使用 Deep Agents / LangGraph 执行。监督器不请求模型判断是否卡住，而是按实际活动续期，持续无活动才进入停止和交接。

## 框架与三类数据的归属

TeamState 包含 agents、tasks 和 mailboxes。协调图只应用按 ID 的 reducers，不调用模型，也不继承子图 checkpoint。业务变更追加到现有 Team JSONL，落盘成功后更新 State。records 属性只是 State 的访问入口，不是另外三份可写状态。

完整对话、工具结果和消息 parent_id 仍保存到任务会话 JSONL。任务持有的运行容器另有内存 checkpoint，用于当前进程内继续执行；它不替代完整历史，也不声称能跨程序重启恢复原图。

## 派发前，把目标、依赖和验收要求说清楚

主 Agent 使用 create_task 定义目标、depends_on、acceptance 和 scope，再用 spawn_agent 指定 task_id。简便的直接委派会自动建立任务。子成员不能随意认领另一个任务，重新分工由 lead 负责。

派发说明从看板生成，附上依赖负责人、上游结果和产物引用、验收条件及修改范围。依赖不满足时查询结果显示 blocked_by；上游 worker 除了任务验收通过，还必须把代码合入主分支，随后创建的下游 worktree 才有输入版本。

worker 的 scope 是工作区相对文件或目录，空列表表示整个自有工作区。文件写入后端与 Bash 沙箱同时落实范围，不能只在提示词里写一句限制。

## 邮件是沟通，不是完成证明

## 任务结束以后，先验收再合并

Agent completed 只表示本轮执行结束。任务进入 submitted，lead 用 update_task 决定是否验收为 done。任务状态迁移、负责人和 generation 统一校验，子 Agent 不能自行宣布验收通过。

交付包含简短 result、artifact_refs 和 checks。检查项填写 name、passed/failed/not_run 及实际 output_id。程序读取真实工具结果核对状态和退出码；worker 命令的证据还要对应提交代码树。代码改变后旧测试不能直接证明新版本通过。lead 仍要判断这些检查是否满足需求。

大日志、报告和 diff 留在已有文件与工具输出中。artifact_refs 引用 output_id，或 worker 变更文件的 file:相对路径。看板不复制完整输出。

merge_agent 要求 worker 已完成、任务已验收、依赖已集成、审查指纹仍有效，并继续使用原有强制用户审批。合并冲突保留工作区，不因为成员结束就删除成果。

## 有实际活动就续期

## A 停止确认后，由 B 继续同一个任务

lead 可以调用 handoff_task；无活动超时和允许重试的模型连接故障也可以自动发起交接。程序先标记 stopping、取消旧 driver，等待工具清理。停止未确认则记录 stop_unconfirmed，不能启动 B。旧执行后来退出才变为 interrupted。

确认停止后，程序更换负责人和执行代次，保留 session_id、run_id、thread_id、worktree、完整历史和内存 checkpointer，相关未处理邮件改投新成员。B 重建模型与工具资源，继续原任务；不是再保存一次用户输入，也不是从干净的 HEAD 重做。

ToolSearch 披露结果、已完成结果和文件读取版本随任务衔接。中断中的写操作保存效果不确定的结果，恢复时不盲目执行旧写调用。B 如需新的操作，仍走正常权限与审批。

如果 A 在停止期间已正常完成，则提交验收，不再替换。权限拒绝、测试不通过或依赖未满足不能通过换人绕过。

## 取消与程序重开

普通 cancel_agent 结束任务执行，并保留原有取消语义；交接使用独立的暂停路径，不提前写 run_end 或销毁任务 checkpoint。旧代次的事件和提交都不能影响接管后的任务。

整个程序重启后，TeamState 和原始历史可以从 JSONL 恢复，内存 checkpoint 已消失。旧活跃执行标为 interrupted，不自动续跑；用户明确发起的新运行使用历史重新开始。当前进程内交接与这种重新开始严格区分。
