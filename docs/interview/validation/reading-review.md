# 本轮导读修订与检查

用户指出初稿把名词和职责分开罗列，没有把函数为什么调用、结果交给谁讲通。因此初稿没有提交，正文和函数卡片说明都按连续任务重写。

## 现在怎样带读

用“给 parser.py 增加空输入处理并运行测试”贯穿各章。00先走完整路线；01解释目录、模型设置、选择模块、打开会话以及真正启动运行。后续章节依次接着消息、请求、工具、长对话、审查、外部调用、会话恢复和界面继续讲，不要求先背一组类名。

每步说明写出上一步还缺什么、为什么调用这里、传入什么、结果由谁接着使用。框架用法和组装方式在具体过程后解释；表格用于回查。代码默认折叠，函数前的说明直接可读，展开后才看完整源码和辅助方法。

## 复读中发现并修正的问题

- 组装对象之后原来直接跳到了模型工作。现在补上返回RuntimeContainer、launcher调用runtime.run、build建图、invoke启动图的关系。
- 命令示例只写-p，原来没有解释为何进入execute_run。现在按实际解析、配置、转换命令的顺序补齐。
- Memory模块原来笼统承包AGENTS说明。现在分清Context选择允许路径、Agent安装框架读取方法、Memory管理JSON笔记。
- 完成状态不自动广播给子Agent；团队发送和接收消息单独解释。
- 压缩章先解释仍需保留的消息、旧输出可以不再完整发送、摘要采用前重新核对，再给出代码字段供定位。
- 评测章分清测试与差异检查先写日志、JUnit和补丁，save_result再整理保存相关材料，不把所有写入归给同一个函数。

交叉复读细节见cross-state.md、cross-runtime.md中的V2记录。机械检查只能找出缺失说明和错误引用；它不能证明所有读者都一定读懂，不能用代码卡片数量代替阅读质量。
