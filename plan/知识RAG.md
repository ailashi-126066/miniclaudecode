# 知识 RAG 方案

## 目标

解决代码生成中的“隐形知识”问题：模型在生成或修改代码前，应当知道工作区有哪些业务规则、接口规范、产品需求和外部资料，并在任务相关时取得原文依据。

知识 RAG 不替代 `MEWCODE.md`、`AGENTS.md` 或项目记忆：不可违反的规则仍直接注入上下文；知识 RAG 负责较长、较多、按需读取的参考资料。

## 存储结构

```text
.mewcode/
├─ knowledge/                 # 原始私有知识文件，唯一事实来源
│  ├─ payment-rules.md
│  ├─ partner-api.docx
│  └─ auth-spec.pdf
└─ knowledge-index/           # 可删除、可重建的派生数据
   ├─ lucene/                 # BM25 倒排索引、KNN 向量、chunk 正文与元数据
   ├─ fingerprints.properties # 文件哈希、大小、修改时间
   ├─ catalog.json            # 供模型了解知识范围的精简目录
   └─ sync.lock
```

- `knowledge/` 支持 Markdown、普通文本、PDF、DOCX、XLS/XLSX、CSV/TSV 与 HTML。
- 索引器提取正文后按标题、段落或递归文本块切分为 chunk。
- 每个 chunk 写入 Lucene 的 `search_text`、`symbol_text`、`path_text`、`vector`、`content`、路径和行号字段。
- 知识目录 `catalog.json` 为派生数据，保存文件路径、标题、摘要、标签、更新时间和内容哈希；原文变化后随索引同步更新。

## 检索与触发

默认模式为 `auto`，即“条件主动检索”，而不是每条消息盲目搜索。

```text
用户消息
→ 先读取已注入的知识目录
→ 本地路由判断
   ├─ 明确要求查规范、文档、知识库：强制检索
   ├─ 生成/修改/调试代码，且包含业务、接口、协议、规则、领域术语：自动检索
   ├─ 闲聊、斜杠命令、简单文件操作：不预取
   └─ 不确定：不预取，但 Agent 可调用 KnowledgeSearch
→ 混合检索、重排与相关性过滤
→ 仅注入高相关的少量来源片段
```

路由使用本地规则：代码块、文件路径、扩展名、符号格式，以及中英文的实现、修复、重构、需求、规则、协议、接口等关键词。第一版不增加 LLM 分类调用。

支持三种配置模式：

- `off`：仅提供 `KnowledgeSearch` 工具。
- `auto`：默认模式，按上述路由预取已建立的知识索引。
- `always`：每条消息都检索，仅供有明确需要的用户启用。

### 显式主动检索命令

提供以下用户命令：

```text
/knowledge index             # 首次建立或增量同步知识索引
/knowledge status            # 查看索引是否可用、是否落后于知识文件
/knowledge <查询>            # 强制检索已建立的知识库
```

`/knowledge index` 是唯一会建立或更新知识索引的入口。用户将资料放入 `.mewcode/knowledge/` 后，自行决定何时执行该命令；系统启动、文件变化和普通检索均不自动触发文档提取、向量化或重建。

`/knowledge <查询>` 允许用户跳过路由判断，要求当前轮立即检索私有知识库。例如：

```text
/knowledge 退款的金额精度和对账规则
```

查询命令以用户提供的查询调用知识索引，将高相关来源片段作为 `system-reminder` 注入当前对话，再继续处理后续问题。索引不存在、构建中、已落后于知识文件或没有命中时，应明确返回状态与原因；查询命令不隐式建立索引，不得用模型已有知识伪造“已查阅知识库”的结论。

## 上下文策略

### 知识目录始终可见

新会话开始时注入精简的目录提醒，而非全部知识正文：

```text
# Available knowledge
- 支付规则：退款、金额精度、对账约束（payment-rules.md）
- 用户权限：角色、资源与鉴权流程（auth-spec.pdf）
- 外部 API：字段、错误码、限流规则（partner-api.docx）
```

目录让模型知道可查询知识的存在与范围，是解决隐形知识的前提。

### 原文按需注入

- 自动检索仅等待本地 Lucene 查询最多 300 ms；超时、索引构建中或失败时不阻塞对话。
- 每类召回最多保留 3 个不同来源，并受严格 token 预算限制。
- 注入内容包含来源路径、标题/符号和行号，便于模型引用与复查。
- 检索结果是参考上下文；涉及当前源码的判断或修改，仍需通过 `ReadFile` 读取磁盘最新内容。
- 复杂问题或自动结果不足时，模型可调用 `KnowledgeSearch` 进行改写查询或二次检索。

## 检索实现

知识库复用项目现有 Lucene 混合检索：

```text
用户查询
├─ BM25：正文、标题和路径的关键词匹配
├─ 向量检索：查询向量与 chunk 向量的 KNN 近邻搜索
└─ RRF 融合 + 重排：筛选少量高相关 chunk
```

当前本地向量模型是 384 维哈希特征，适合离线与低成本运行，但不是真正的语义 embedding。知识库需要接通可配置的真实 embedding 模型后，才能获得词面不同但语义相近的明显召回收益；BM25 仍保留，用于术语、字段、错误码和精确名称。

## 索引生命周期

- 用户执行 `/knowledge index` 时才同步知识索引；首次执行建立全量索引，后续执行根据文件指纹只更新受影响文件和 chunk。
- 工作区启动、`knowledge/` 文件新增、修改、删除，以及普通自动检索均不自动同步。文件变化会使索引状态标记为 `STALE`，直到下一次用户手动同步。
- 索引器需使用独立扫描范围，因为通用工作区扫描器会忽略整个 `.mewcode/` 目录。
- 同一知识库一次只能执行一个同步任务；短时间内多次命令请求合并为一次同步。
- 索引不可用或过期时，`KnowledgeSearch` 返回明确状态和 `/knowledge index` 提示，Agent 继续使用已有上下文和文件读取工具，不中断任务。

## 工具接口

新增 `KnowledgeSearch` 只搜索知识索引，不与 `CodeSearch` 混用。

```text
KnowledgeSearch(query, top_k?)
→ source path, title/symbol, line range, relevance explanation, text fragment
```

工具描述需要明确说明其数据源是私有知识文档，以便模型在自动预取不足、用户要求依据规范回答或需要二次查找时主动调用。

`/knowledge <查询>` 是面向用户的强制主动检索入口；`KnowledgeSearch` 是面向模型的按需检索工具。两者复用同一知识索引与结果格式。
